## 关键决策

### 决策 1: TUI 库选择 ✅
**日期：** 2025-01-27
**状态：** ✅ 已决定
**最终选择：** **blessed** (^2.0.0)

**理由：**
- ✅ 功能完整：支持所有需求（Tab页、列表、搜索框、进度条、弹窗等）
- ✅ 跨平台兼容：自动处理不同终端的兼容性问题
- ✅ 成熟稳定：8.5k+ stars，经过大量项目验证
- ✅ Vim 键位支持：内建 `vi: true` 选项
- ✅ 丰富的事件系统：易于实现复杂的交互逻辑
- ✅ 颜色和样式：支持完整的颜色方案和样式定制
- ✅ 响应式布局：支持百分比和自动布局

**依赖配置：**
```json
{
  "optionalDependencies": {
    "blessed": "^2.0.0"
  }
}
```

**降级策略：**
```javascript
let tui;
try {
  tui = require('./lib/tui');
} catch (e) {
  console.log('TUI not available. Install with: npm install blessed');
  console.log('Falling back to CLI mode...');
  // 使用原有 CLI 模式
}
```

### 决策 2: 依赖管理 ✅
**日期：** 2025-01-27
**状态：** ✅ 已决定
**方案：** 可选依赖（optionalDependencies）

**配置：**
```json
{
  "optionalDependencies": {
    "blessed": "^2.0.0"
  }
}
```

**实现：**
- blessed 作为可选依赖，不影响核心功能
- 如果未安装 blessed，自动降级到 CLI 模式
- 通过 `try-catch` 检测 TUI 是否可用
- 提示用户安装 blessed 以使用 TUI 功能

**优点：**
- 保持核心功能零依赖
- 用户可选择是否安装 TUI
- 向后兼容现有使用方式

### 决策 3: 配置存储
**状态：** 已决定
**方案：** 不保存选择状态，每次从头开始

**原因：**
- 保持简单
- 避免配置管理复杂性
- 用户倾向于每次重新选择

## 风险和挑战

### 技术风险
1. **跨平台兼容性**
   - Windows 终端差异
   - 不同终端的颜色支持
   - 缓解：充分测试，提供回退方案

2. **性能问题**
   - 大量数据（100+项）的渲染性能
   - 实时搜索的响应速度
   - 缓解：虚拟滚动，增量渲染

3. **依赖管理**
   - 外部依赖违背零依赖原则
   - 缓解：将 TUI 设为可选功能

### 设计风险
1. **学习曲线**
   - Vim 键位对非 Vim 用户不友好
   - 缓解：提供方向键支持，帮助文档

2. **复杂性增加**
   - TUI 增加代码复杂度
   - 缓解：模块化设计，清晰架构
